## 追加：Java 产物合并为「一个 Excel 一个类」

- 起因：用户觉得 19 个 .java 太多。原因写了清楚：C# 是「实体 + 容器」双类型且一个 .cs 可放多个类，
  Java 一个文件只能一个 public 顶层类，照搬结构就变成一类型一文件。
- 方案（用户选定）：一个 Excel 文件 = 一个 `<OutputName>Config.java`，各页签作为 `public static final class`
  嵌套在配置根内；`ExampleConfig.Item` / `ExampleConfig.ItemMap` 这样引用。
- 实现要点：新增 `JavaNames` 记录 + `BuildJavaNames`（文件内类名去重、避开根类同名）；
  `BuildJavaFile` 统一拼 package/imports/根类/内部类；`Indent(text, 4)` 把内部类整块右移。
  import 按需输出（JsonNode / ArrayList / HashMap / List / Map / BiConsumer）。
- 结果：2 个 Excel 从 19 个文件降到 8 个（2 配置根 + 4 运行时 + Enums + ExcelData），1187 行。
  附带好处：不同 Excel 有同名页签也不再冲突（各自嵌套）。
- 验证：`javac -Xlint:all` 编译客户端/服务端与仓库示例产物零警告；冒烟测试全部通过
  （多语言、主键/下标/分组、枚举 of、forEach、语言回退）。README 已同步新结构与引用写法。

## 追加：Java 产物收成 2 个文件

- 用户要求把「几个 Config 文件 + ConfigRow / ConfigTable / ConfigValue」合并成一个文件。
- 实现：`GenerateJava(List<(ExcelFileData File, List<TableSchema> Schemas)>, javaDir)` 一次性输出
  `ExcelData.java`，内含：入口（load / initLanguage / getXxxConfig）+ 运行时（LanguageManager /
  ConfigTable / ConfigRow / ConfigValue，均为 static 内部类）+ 各 Excel 配置根（内部再嵌页签类）。
  `Enums.java` 作为唯一另一个文件保留（顶层类，产物内引用 `Enums.X` 靠同包解析）。
- 关键约束：Java 一个文件只能有一个 public 顶层类；内部类名需避开运行时类型名
  （`JavaReservedTypeNames`）与根类名，`BuildJavaNames` 统一去重。
- 结构影响：Program.cs 现在先把所有 Excel 的 Schema 构建成 `builtFiles`，Java 一次生成，
  TS / C# / JSON 仍在循环里逐文件生成（复用同一份 schemas）。
- getter 命名统一为 `get{Type}()`：`data.getExampleConfig()`、`cfg.getItemMap()`。
- 结果：2 个 Excel → ExcelData.java（~1100 行）+ Enums.java，共 2 个文件。
- 验证：`javac -Xlint:all` 客户端/服务端/仓库示例零警告；冒烟测试全过；
  重新生成 OutputExp（TS/C#/JSON）与改前字节一致，未影响其他语言产物。

## 追加：Java 回到「每表格一个文件 + 运行时合并」

- 用户要求：每个表格仍导出一个 .java，但运行时那几个类合并。
- 现状布局（2 个 Excel 共 5 个文件）：`ExcelData.java`（入口）、`ConfigRuntime.java`
  （public final class，内部嵌 LanguageManager / ConfigTable / ConfigRow / ConfigValue，
  全部 static 且包内可见）、`ExampleConfig.java` / `AttrConfig.java`（每 Excel 一个，页签是内部类）、`Enums.java`。
- 踩坑：把多个「包内可见顶层类」放在一个文件里，javac -Xlint 报
  `auxiliary class ... should not be accessed from outside its own source file`（能编译但脏）。
  最终改为「一个 public 外层类 + 嵌套包内类」，各配置根用
  `import game.config.ConfigRuntime.ConfigRow;` 等导入，生成代码里的类名保持原样不变。
- 其它：`ExcelData` 增加 `getText(key)` 作为多语言对外入口（LanguageManager 已包内可见）；
  实体构造函数改为包内可见，避免 public API 暴露包内类型。
- 验证：`CLASSPATH= javac -Xlint:all` 客户端/服务端/仓库示例零警告零错误；
  冒烟测试全过；OutputExp（TS/C#/JSON）重新生成后与改前无差异。
