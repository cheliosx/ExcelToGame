## 追加：Java 运行时改为依赖 Jackson

- 按用户要求去掉自写的 `Json.java`，改用 `com.fasterxml.jackson.databind`
  （`ObjectMapper.readTree` / `JsonNode`），运行时只剩 4 个类：
  `ConfigValue` / `ConfigRow` / `ConfigTable` / `LanguageManager`。
- 行数据的懒解析结构不变：`ConfigRow.values()` 返回 `JsonNode[]`，首次访问才 `readTree` 该行；
  `ConfigTable` 只存行文本，`readKey` 仍是纯字符串扫描（不建 JsonNode）。
- `loadSection` 参数由 `Object` 改为 `JsonNode`；参数表用 `fields.has(...)` / `fields.get(...)`。
- 依赖坐标写进 README 与 `ConfigValue` 的 javadoc：`jackson-databind 2.17.2`（2.13+ 均可）。
- 验证：下载 jackson 2.17.2 三个 jar 到临时目录，`javac -Xlint:all` 编译客户端/服务端两套产物
  与仓库内示例产物，均无警告；冒烟测试覆盖多语言、主键/下标/分组、枚举 `of()`、
  `toIntList/toStrList/toBoolList/toDoubleList/toEnumList/toObject`、`readKey`、`toRows`，结果正确。


## 追加：Java 产物合并为「一个 Excel 一个类」

- 起因：用户觉得 19 个 .java 太多。原因写了清楚：C# 是「实体 + 容器」双类型且一个 .cs 可放多个类，
  Java 一个文件只能一个 public 顶层类，照搬结构就变成一类型一文件。
- 方案（用户选定）：一个 Excel 文件 = 一个 `<OutputName>Config.java`，各页签作为 `public static final class`
  嵌套在配置根内；`ExampleConfig.Item` / `ExampleConfig.ItemMap` 这样引用。
- 实现要点：新增 `JavaNames` 记录 + `BuildJavaNames`（文件内类名去重、避开根类同名）；
  `BuildJavaFile` 统一拼 package/imports/根类/内部类；`Indent(text, 4)` 把内部类整块右移。
  import 按需输出（JsonNode / ArrayList / HashMap / List / Map / BiConsumer）。
- 结果：2 个 Excel 从 19 个文件降到 8 个（2 配置根 + 4 运行时 + Enums + ExcelData），1187 行。
  附带好处：不同 Excel 有同名页签也不再冲突（各自嵌套）。
- 验证：`javac -Xlint:all` 编译客户端/服务端与仓库示例产物零警告；冒烟测试全部通过
  （多语言、主键/下标/分组、枚举 of、forEach、语言回退）。README 已同步新结构与引用写法。
